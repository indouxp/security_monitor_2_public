# クライアント メトリクス選択

## 概要

フェーズ4のリソース監視パネルにおける、クライアント側の取得メトリクスを確定する。

---

## 選択結果

| メトリクス | 採用 | 理由 |
|---|---|---|
| CPU 使用率 | ✓ | WebRTC H.264 ソフトウェアデコードで常時高負荷になりやすい |
| CPU 温度 | ✓ | CPU 負荷に連動して上昇。サーマルスロットリングの早期検知に有効 |
| メモリ使用率 | ✓ | Chrome + 3ストリーム分の映像バッファで消費量が積み上がる |
| ディスク使用率 | — | ストリーミング再生はディスクに書き込まないため優先度低。除外 |

---

## 各メトリクスの詳細

### CPU 使用率

ストリーミング中に最も変動が大きく、優先度最高。

| 項目 | 内容 |
|---|---|
| 取得元 | `/proc/stat` |
| 計算方法 | 1秒間の `user + nice + system` 増分 ÷ 全 CPU 時間増分 × 100 |
| 更新推奨間隔 | 5〜10秒 |
| 注意点 | 瞬間値は振れが大きいため、直前との差分（1秒間隔）で計算する |

```
/proc/stat の読み取り例（1行目が全コア合計）:
cpu  123456 0 45678 9012345 ...
     ^user    ^sys  ^idle
```

---

### CPU 温度

CPU 使用率と合わせて監視することで、サーマルスロットリングの予兆を捉えられる。

| 項目 | 内容 |
|---|---|
| 取得元 | `/sys/class/thermal/thermal_zone0/temp` |
| 単位変換 | 取得値は 1/1000 ℃単位（例: `55000` → `55.0℃`） |
| 更新推奨間隔 | 5〜10秒 |
| 注意点 | `thermal_zone` の番号はハードウェアによって異なる。複数ある場合は最大値を使用する |

```bash
# 全 thermal_zone の最大温度を取得する例
cat /sys/class/thermal/thermal_zone*/temp | sort -n | tail -1
```

---

### メモリ使用率

Chrome 起動後は一定量で安定するが、長時間稼働でのメモリリークの検知に有効。

| 項目 | 内容 |
|---|---|
| 取得元 | `/proc/meminfo` |
| 計算方法 | `(MemTotal - MemAvailable) ÷ MemTotal × 100` |
| 更新推奨間隔 | 30秒（変動が緩やかなため） |
| 注意点 | `MemFree` ではなく `MemAvailable` を使う（ページキャッシュを考慮した実使用量になる） |

```
/proc/meminfo の読み取り例:
MemTotal:        4096000 kB
MemFree:          512000 kB
MemAvailable:    1024000 kB   ← こちらを使用
```

---

## 更新間隔まとめ

| メトリクス | 推奨間隔 | 理由 |
|---|---|---|
| CPU 使用率 | 5〜10秒 | 変動が大きく、リアルタイム性が求められる |
| CPU 温度 | 5〜10秒 | CPU 使用率と同期して監視したい |
| メモリ使用率 | 30秒 | 変動が緩やかで高頻度更新の必要性が低い |

metrics-agent の実装では、CPU 使用率・CPU 温度・メモリ使用率を **同一エンドポイントで返す**。  
更新間隔はブラウザ側の fetch 周期で制御する。
