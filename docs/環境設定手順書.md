## 1. 前提条件

### 1.1 各ホストの要件

| ホスト | OS | 必要パッケージ | 備考 |
|---|---|---|---|
| rpi4-1 | Raspberry Pi OS (Debian系) | Python3、nginx、coturn、systemd | 映像中継・WebUI・メトリクスサーバー |
| rpi4-0 | Raspberry Pi OS (Debian系) | samba、cron | AtomCam録画受信サーバー |
| AtomCam 3台 | - | atomcam_tools（microSD） | RTSP配信・NAS録画を有効化 |
| Linuxクライアント (vostro等) | Ubuntu/Debian系 | bash、curl、systemd | メトリクス収集・送信 |
| Windowsクライアント | Windows 10/11 | PowerShell 5.1以上 | 管理者権限が必要 |

### 1.2 ネットワーク要件

- 全ノードが同一LAN（192.168.0.0/24）に接続していること
- クライアント → rpi4-1 の TCP:80（HTTP）が疎通していること
- クライアント → rpi4-1 の UDP:3478（STUN）が疎通していること
- rpi4-1 → AtomCam 3台 の TCP:8554（RTSP）が疎通していること
- AtomCam 3台 → rpi4-0 の TCP:445（Samba）が疎通していること
- `rpi4-1.tsystem.gr.jp` の名前解決ができること（またはhostsファイル設定）

### 1.3 SSHアクセス

- 作業端末から `indo@rpi4-1` へのSSHパスワードなし接続が設定済みであること
- 作業端末から `indo@rpi4-0` へのSSHパスワードなし接続が設定済みであること
- 作業端末から `indou@vostro` へのSSHパスワードなし接続が設定済みであること

### 1.4 リポジトリの確認

```bash
# 作業端末で実行
git -C /home/indo/Public/security_monitor_2 status
```

## 2. AtomCam セットアップ（atomcam_tools）

### 2.1 microSDへのatomcam_toolsインストール

AtomCam 3台それぞれに対して以下を実施します。

1. microSDカードをPCに接続します
2. `atomcam_tools.zip` をダウンロードし、microSDのルートに展開します
3. microSDをAtomCamに戻し、電源を入れます
4. AtomCamが起動してLANに接続されるまで待ちます（約1分）

### 2.2 RTSP有効化

1. ブラウザで `http://[AtomCamのIP]/` にアクセスします
2. atomcam_tools管理画面の「ストリーミング」メニューを開きます
3. RTSPを「有効」に設定します
4. 設定を保存します

RTSP URLの形式: `rtsp://[IP]:8554/video0_unicast`

| カメラ | IPアドレス | RTSP URL |
|---|---|---|
| AtomCam Swing #1（二階左） | 192.168.0.12 | rtsp://192.168.0.12:8554/video0_unicast |
| AtomCam 2（玄関） | 192.168.0.7 | rtsp://192.168.0.7:8554/video0_unicast |
| AtomCam Swing #2（二階右） | 192.168.0.16 | rtsp://192.168.0.16:8554/video0_unicast |

### 2.3 NAS録画設定（rpi4-0 Samba接続）

1. atomcam_tools管理画面の「録画」→「NAS設定」を開きます
2. 以下を設定します

| 項目 | 設定値 |
|---|---|
| ホスト/IP | rpi4-0（192.168.0.58） |
| 共有名 | usb_share |
| ユーザー | （空欄 ゲスト） |
| パスワード | （空欄 ゲスト） |

3. 設定を保存します

### 2.4 確認方法（AtomCam）

```bash
# rpi4-1 から RTSP 疎通確認（ffprobeが利用可能な場合）
ssh indo@rpi4-1 "ffprobe -v quiet -show_streams rtsp://192.168.0.12:8554/video0_unicast 2>&1 | head -5"

# rpi4-0 で録画ファイルが書き込まれているか確認
ssh indo@rpi4-0 "ls -la /mnt/usb_share/ | head -20"
```

録画ファイルの期待する形式: `YYYYMMDD/HH/YYYYMMDDHHmmss.mp4`（1分セグメント）

## 3. rpi4-0 セットアップ（録画受信サーバー）

### 3.1 パッケージインストール

```bash
ssh indo@rpi4-0 "sudo apt update && sudo apt install -y samba"
```

### 3.2 USB SSD マウント設定

```bash
# デバイス確認
ssh indo@rpi4-0 "lsblk && sudo fdisk -l /dev/sda"

# マウントポイント作成
ssh indo@rpi4-0 "sudo mkdir -p /mnt/usb_share"

# 手動マウント確認
ssh indo@rpi4-0 "sudo mount /dev/sda1 /mnt/usb_share && df -h /mnt/usb_share"

# UUID確認
ssh indo@rpi4-0 "sudo blkid /dev/sda1"
```

fstab設定（UUID は `blkid` コマンドで確認した値に置換します）:

```bash
ssh indo@rpi4-0 "echo 'UUID=\"8ec42eba-a32d-4e5a-b6c9-e395d20263b6\" /mnt/usb_share ext4 defaults,noatime 0 2' | sudo tee -a /etc/fstab"
ssh indo@rpi4-0 "sudo mount -a && df -h /mnt/usb_share"
```

### 3.3 共有ディレクトリのパーミッション設定

```bash
ssh indo@rpi4-0 "sudo chmod 777 /mnt/usb_share"
```

### 3.4 Samba 設定

```bash
ssh indo@rpi4-0 "sudo tee -a /etc/samba/smb.conf << 'EOF'

[usb_share]
   comment = for atomcam
   path = /mnt/usb_share
   browseable = yes
   writable = yes
   guest ok = yes
   create mask = 0777
   directory mask = 0777
   guest only = yes
EOF"

# 設定確認
ssh indo@rpi4-0 "testparm"

# 再起動・有効化
ssh indo@rpi4-0 "
    sudo systemctl restart smbd nmbd && \
    sudo systemctl enable smbd nmbd
"
```

### 3.5 rsync cron 設定（macmini2010 へ）

rpi4-0からmacmini2010（192.168.0.206）の外部USBへrsyncします。  
macmini2010へのSSHパスワードなし設定が必要です。

```bash
# rsync スクリプトの作成
ssh indo@rpi4-0 "cat > /home/indo/bin/rsync-to-macmini.sh << 'SCRIPT'
#!/bin/bash
SRC=/mnt/usb_share/
DST=indo@192.168.0.206:/path/to/external_usb/atomcam/
rsync -avz --delete "\$SRC" "\$DST" >> /var/log/atomcam-rsync.log 2>&1
SCRIPT
chmod +x /home/indo/bin/rsync-to-macmini.sh"

# cron 登録
ssh indo@rpi4-0 "crontab -l 2>/dev/null | { cat; echo '10 * * * * /home/indo/bin/rsync-to-macmini.sh'; } | crontab -"
```

> **注意**: `DST` のパスはmacmini2010の外部USBのマウントポイントに合わせて変更してください。

#### (2) USB SSD マウント確認

### 4.2 MediaMTX インストールと設定

```bash
# インストールディレクトリ作成
ssh indo@rpi4-1 "sudo mkdir -p /opt/mediamtx"

# バイナリダウンロード（ARM64版）
ssh indo@rpi4-1 "
    wget -O /tmp/mediamtx.tar.gz \
        https://github.com/bluenviron/mediamtx/releases/download/v1.18.1/mediamtx_v1.18.1_linux_arm64v8.tar.gz && \
    sudo tar xzf /tmp/mediamtx.tar.gz -C /opt/mediamtx && \
    sudo chmod +x /opt/mediamtx/mediamtx
"
```

設定ファイルを作成します（`/opt/mediamtx/mediamtx.yml`）:

```bash
ssh indo@rpi4-1 "sudo tee /opt/mediamtx/mediamtx.yml << 'EOF'
logLevel: info
logDestinations: [file]
logFile: /var/log/mediamtx.log

rtsp: yes
rtspAddress: :8554

webrtc: yes
webrtcAddress: :8889

hls: yes
hlsAddress: :8888

api: yes
apiAddress: :9997

paths:

  # AtomCam Swing #1（二階部屋左側）
  swing1:
    source: rtsp://192.168.0.12:8554/video0_unicast
    sourceOnDemand: no

  # AtomCam 2（玄関）
  atomcam2:
    source: rtsp://192.168.0.7:8554/video0_unicast
    sourceOnDemand: no

  # AtomCam Swing #2（二階部屋右側）
  swing2:
    source: rtsp://192.168.0.16:8554/video0_unicast
    sourceOnDemand: no
EOF"
```

> **注意**: `sourceReconnectPause` は MediaMTX v1.18.1 で廃止されています。設定ファイルに含めると起動失敗します。

systemdサービスを作成します:

```bash
ssh indo@rpi4-1 "sudo tee /etc/systemd/system/mediamtx.service << 'EOF'
[Unit]
Description=MediaMTX RTSP/WebRTC Server
After=network.target

[Service]
User=root
WorkingDirectory=/opt/mediamtx
ExecStart=/opt/mediamtx/mediamtx /opt/mediamtx/mediamtx.yml
Restart=always
RestartSec=5s

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now mediamtx"
```

## 5. vostro セットアップ（表示端末・メトリクスクライアント）

vostroは2つの役割を担います:
- **表示端末**: Chromeキオスクモードでセキュリティモニター画面を常時表示
- **メトリクスクライアント**: push_metrics.shでリソース情報をrpi4-1へ送信

### 5.1 キオスクモード設定

#### (1) 起動スクリプト作成

```bash
ssh indou@vostro "cat > /home/indou/start-camera-monitor.sh << 'EOF'
#!/bin/bash
# スクリーンセーバー・画面オフを無効化
xset s off
xset -dpms
xset s noblank

# Chromeをキオスクモードで起動
# --mute-audio: WebRTC音声をPipeWireに送信しない（大音量防止）
google-chrome-stable \
    --kiosk \
    --mute-audio \
    --noerrdialogs \
    --disable-infobars \
    --disable-session-crashed-bubble \
    --disable-restore-session-state \
    --no-first-run \
    --start-fullscreen \
    --password-store=basic \
    http://rpi4-1.tsystem.gr.jp/
EOF
chmod +x /home/indou/start-camera-monitor.sh"
```

#### (2) XDG Autostart 設定（ログイン時自動起動）

```bash
ssh indou@vostro "
    mkdir -p /home/indou/.config/autostart && \
    cat > /home/indou/.config/autostart/camera-monitor.desktop << 'EOF'
[Desktop Entry]
Type=Application
Name=Camera Monitor
Comment=防犯カメラモニター
Exec=/home/indou/start-camera-monitor.sh
X-GNOME-Autostart-enabled=true
EOF"
```

#### (3) キオスクモード確認

vostroにログインしたとき、Chromeが自動起動して `http://rpi4-1.tsystem.gr.jp/` が全画面表示されることを確認します。

## 6. Windowsクライアント環境構築

### 6.1 スクリプトの配置

以下のファイルを Windows 機の任意のフォルダにコピーします（例: `C:\SecurityMonitor\`）。

| ファイル | 説明 |
|---|---|
| `inventory/client/win/push_metrics.ps1` | メトリクス収集スクリプト |
| `inventory/client/win/register_task.ps1` | タスクスケジューラ登録スクリプト |
| `inventory/client/win/run_hidden.vbs` | タスクスケジューラからの起動用VBScript（画面フラッシュ防止） |

> **注意**: `run_hidden.vbs` は `register_task.ps1` と同じフォルダに配置してください。  
> タスクスケジューラは `wscript.exe run_hidden.vbs` を呼び出し、  
> VBScript が `WScript.Shell.Run(..., 0, True)` で `push_metrics.ps1` を完全に不可視で起動します。

### 6.2 PowerShell ExecutionPolicy の設定

PowerShell のデフォルト実行ポリシーは `Restricted`（スクリプト実行禁止）のため、
事前に変更が必要です。**管理者として PowerShell を起動**し、以下を実行します（一度のみ）。

```powershell
# 現在のポリシーを確認
Get-ExecutionPolicy

# スクリプトの実行制限を解除する
Set-ExecutionPolicy Bypass -Scope LocalMachine

# 確認
Get-ExecutionPolicy
# -> Bypass
```

> **補足**: `register_task.ps1` はタスクスケジューラ経由で `push_metrics.ps1` を
> `-ExecutionPolicy Bypass` で呼び出すため、スケジュール実行自体はポリシーの影響を受けません。
> ただし `register_task.ps1` 自体を実行する PowerShell セッションのポリシーが
> `Restricted` だと起動できません。

### 6.3 DNS名前解決の確認と設定

`rpi4-1.tsystem.gr.jp` が解決できることを確認します。

```powershell
ping rpi4-1.tsystem.gr.jp
```

解決できない場合、WSL2インストール済み環境では Hyper-V 仮想スイッチが DNS クエリに干渉し、
プライベートドメインの名前解決に失敗することがあります。

**対処: NRPT（名前解決ポリシーテーブル）の設定**

**管理者として PowerShell を起動**し、以下を実行します（一度のみ）。

```powershell
# tsystem.gr.jp ドメインのDNSを 192.168.0.254 に強制する
Add-DnsClientNrptRule -Namespace ".tsystem.gr.jp" -NameServers "192.168.0.254"

# 設定確認
Get-DnsClientNrptRule | Where-Object { $_.Namespace -like "*tsystem*" }

# DNSキャッシュをクリアして再確認
ipconfig /flushdns
ping rpi4-1.tsystem.gr.jp
```

> **補足**: WSL2 の Hyper-V 仮想ネットワークアダプターは `192.168.0.254` より先に NXDOMAIN を
> 返すことがあります。NRPT を設定すると、対象ドメインのクエリは常に指定したDNSサーバーへ送られます。
> この設定はシステム再起動後も維持されます。

{"hostname":"windows-pc","ts":"2026-05-11T13:20:00","cpu":25.3,"temp":0.0,"disk_rw":102400,"mem":52.1,"mem_total":16777216}
